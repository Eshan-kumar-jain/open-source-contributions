NUMPY-FINANCIAL - ISSUE #58
===========================

Issue:   https://github.com/numpy/numpy-financial/issues/58
My PR:   https://github.com/numpy/numpy-financial/pull/155
Branch:  tst-npv-irr-edge-cases
File:    numpy_financial/tests/test_financial.py


THE ISSUE
---------
"We need more thorough test coverage." The maintainers said the tests for
many numpy-financial functions were sparse, especially for edge cases, and
asked contributors to add more to test_financial.py. It is labelled
"good first issue" and covers every function in the library.

I took on part of it: the npv (net present value) and irr (internal rate
of return) functions.


WHAT I DID
----------
1. Fixed the development environment. The first test run failed before
   any test executed, for three reasons:
     - the hypothesis package was missing
     - numpy-financial contains a Cython module, so the package has to be
       compiled before it can be tested
     - the current main branch needs Python 3.13, and my existing
       environment was Python 3.11
   Fix: a separate conda environment (Python 3.13), the build tools, and
   an editable build with:  pip install --no-build-isolation -e .

2. Added five edge case tests:
     npv:  zero interest rate
           all-negative cashflows
           a single cashflow
     irr:  a single positive cashflow
           zero cashflows in the middle of the series

3. Fixed a mistake in one of my own tests. The "zeros in the middle" test
   expected an IRR of 9% for [-100, 0, 0, 130.301], but the correct answer
   is about 9.22%, because 1.09^3 = 1.295029, not 1.30301. Instead of
   hard-coding a rounded number, the test now calculates the exact
   expected value: 1.30301 ** (1/3) - 1.

4. Checked everything: all 115 tests in the file passed, and the ruff
   linter reported no problems.

5. Committed, pushed to my fork, opened PR #155 against numpy/numpy-financial,
   and linked it from issue #58.


BUGS I FOUND ALONG THE WAY
--------------------------
While testing I found two inputs where irr crashes with an unhelpful error
instead of handling the input:

  - npf.irr([])                     -> IndexError
    (the code reads row[0] without checking whether the row is empty)

  - npf.irr([-100, np.nan, 110])    -> LinAlgError from np.roots
    (whereas npv simply returns NaN for NaN input)

I confirmed both on my own build and reported them in the PR description
instead of writing tests for them, because the maintainers first need to
decide what the correct behaviour should be.
